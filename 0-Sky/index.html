What it is for

One guarded workflow for an authorized research device.

0-Sky packages the host orchestration, pinned runtime dependencies, installation images, and companion helpers needed to prepare an Apple SRD from a supported Mac.

01

Validate authorization

Confirms the exact USB target, Lockdown pairing, RemoteXPC path, research-enabled identity, research nonce, and TSS personalization before mutation.

02

Provision secure access

Installs or verifies the research Cryptex, Dropbear SSH service, Procursus rootless environment, and caller-owned SSH identity.

03

Install the toolset

Installs or verifies CATVNC, CrypStore, the 0-Sky research Cryptex, and the reviewed Filza 4.0 Cryptex.

04

Prepare macOS

Checks the Apple host services, Xcode SDK, Python environment, command-line dependencies, and at least 4 GiB of free workspace.

05

Bind the bridge

Creates per-device LaunchAgents for exact-UDID USB forwarding, the protected CrypStore worker, and the native device-bridge supervisor.

06

Verify the result

Applies post-install version, root-access, pairing, and service gates. A failed gate stops the workflow instead of reporting success.

!
This is not a retail-device conversion or bypass.

The connected device must already be an Apple-authorized, research-enabled SRD. A retail iPhone or iPad with img4_chip_rsch != 1 is intentionally rejected.

Before starting

Requirements

Use a dedicated Mac and a direct, reliable USB connection. Keep the target unlocked while pairing or approving host access.

  • Apple silicon MacThe published executable is a native arm64 Mach-O binary.
  • Full Xcode with an iPhoneOS SDKApple command-line tools alone may not provide every required SDK or SRD host service.
  • Authorized Apple Security Research DeviceTarget iOS 17–27, already entitled as research-enabled by Apple.
  • USB pairing and trustConnect directly, unlock the device, accept Trust, and approve the Mac when requested.
  • Homebrew and Python 3.12Needed when the checked host tools or bootstrap interpreter are not already installed.
  • At least 4 GiB freeRequired for extraction, Cryptex preparation, logs, and temporary workspaces.
  • Internet access during personalizationApple TSS access is needed to request target-specific Cryptex tickets.

How to run it

Download. Verify. Check. Run.

Commands below assume Terminal is open in a new working directory. The default display shows a compact percentage flow.

Download the current binary

Fetch the Git LFS release directly from the main branch.

curl -fL -o 0sky \
  https://github.com/fuzzlove/liquidskysecurity/raw/refs/heads/main/0-Sky/0sky
chmod 700 ./0sky

Verify the published checksum

Do not run the download if its digest does not match.

echo "189b98a047d3f15ab90134638d07593ea6ee50d5cdd800be72bee3600624a4ff  0sky" \
  | shasum -a 256 -c -

Connect and preflight the SRD

Connect one unlocked device by USB. This read-only pass validates the kit, target, RemoteXPC research path, nonce, and TSS response.

./0sky --check

Run the workflow

If preflight passes, start the complete install. Keep the Mac awake and the USB cable connected through reboots and reconnection checks.

./0sky

Select an exact device when needed

Automatic target selection works when one compatible USB device is connected. With more than one, provide the intended UDID explicitly.

./0sky --udid YOUR_AUTHORIZED_SRD_UDID

FAQ

Important boundaries

Will this work on a retail iPhone or iPad?

No. 0-Sky requires an Apple Security Research Device with the research-enabled identity set by Apple. It does not add that entitlement, bypass it, or turn a retail device into an SRD.

Does the UDID update automatically?

Yes, when exactly one compatible USB device is visible. If several devices are attached, 0-Sky refuses ambiguous selection and requires --udid ID. Companion services are bound to that exact UDID.

What macOS daemons are installed?

Three per-device user LaunchAgents: an exact-UDID USB/iproxy forward, a protected CrypStore worker, and a native device-bridge supervisor. Sanitized templates and checksums are available in the macOS daemon bundle.

Why can preflight fail at RemoteXPC or TSS?

The target may not be research-enabled, the Mac may not be paired, an Apple host service may be unavailable, or personalization may be denied. Unlock the authorized SRD, approve the Mac, confirm the USB connection and network, then retry. Authorization failures are intentionally fail-closed.

Is this a complete-device restore tool?

No. This workflow installs and validates research Cryptex components; it is not a replacement for Apple’s official SRD restore procedure or full-device restore tooling.

What if macOS blocks the downloaded binary?

The current build is ad-hoc signed rather than Apple-notarized. First verify the SHA-256 value shown above. If you trust the verified file, use the macOS Privacy & Security panel to review the block and choose Open Anyway. Do not disable Gatekeeper globally.

Where are diagnostic artifacts?

On failure, follow the artifact path printed by the tool and review the per-stage report. Error codes E130–E138 identify setup and workflow-stage failures.
